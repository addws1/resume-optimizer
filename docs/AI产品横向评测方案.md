# AI 产品横向评测方案（四维 · 12 指标）

> 评测对象：豆包、Kimi、DeepSeek、Coze
> 日常体验积累：2026.03 起 ｜ 系统化评测执行：2026.07
> 评测目的：为自研简历优化工具明确产品定位与差异化方向
>
> **可复现原则**：所有产品使用完全相同的测试材料与提问文本；每项测试记录日期、产品版本、原始输出截图（存 `docs/eval-evidence/` 目录，按 `维度-指标-产品名` 命名）。

---

## 〇、评测前准备（30 分钟）

准备四份统一测试材料，放在 `docs/eval-materials/`：

| 材料 | 内容 | 来源建议 |
|------|------|---------|
| 材料 A | 一段"流水账"原始实习/项目经历（300 字左右，无量化、无 STAR） | 用你自己简历优化前的旧版本，真实 |
| 材料 B | 目标岗位 JD：AI 产品实习生 | 从 BOSS直聘复制一个真实 JD（正好是你要投的） |
| 材料 C | 长文档：2 万字以上的中文行业报告 PDF | 任选一份公开的 AI 行业报告 |
| 材料 D | 对照岗位 JD：后端开发实习生 | 同样从 BOSS直聘复制 |

针对材料 C 预先准备 5 个**事实性问题**（答案在文档不同章节，含 1 个需要跨章节综合的问题），并自己先把标准答案找出来。

**打分方式**：每项指标 1–5 分，按指标下方的锚点描述打分，禁止凭感觉给"都差不多"的分。每项打分必须在打分表"依据"栏写一句话理由。

## 一、对话交互体验（3 项）

### 1.1 意图理解准确性

- **任务**：发送口语化模糊请求："帮我看看这段经历写得行不行"+ 材料 A（不说明目标岗位）
- **观察点**：是否识别出"优化简历"意图？是否主动追问目标岗位等关键缺失信息？
- **锚点**：5 = 准确理解且主动追问关键信息；3 = 理解意图但直接给泛泛建议；1 = 答非所问

### 1.2 多轮上下文保持

- **任务**：连续 5 轮对话。第 1 轮说明"我的目标岗位是 AI 产品实习生"；第 2–4 轮讨论经历细节；第 5 轮问"按我最开始说的岗位，把第一段再改一版"
- **观察点**：第 5 轮是否记得第 1 轮的岗位设定？改的是否是"第一段"？
- **锚点**：5 = 两个指代都准确；3 = 记得岗位但段落指代错；1 = 岗位设定已丢失

### 1.3 交互与呈现设计

- **任务**：沿用 1.1/1.2 的对话过程，从产品视角评价
- **观察点**：输出结构化程度（分点/表格 vs 大段文字）、流式响应体验、是否支持继续追问深挖、修改建议是否好定位
- **锚点**：5 = 结构清晰可直接行动；3 = 内容对但呈现杂乱；1 = 大段糊状文字

## 二、长文档处理能力（3 项）

### 2.1 长文信息提取准确性

- **任务**：上传材料 C，依次提问预设的 5 个事实性问题
- **观察点**：答对几个？错的是"找不到"还是"编造"（编造更严重，单独记录）
- **锚点**：5 = 5/5 全对；4 = 4/5；3 = 3/5；2 = 2/5 或出现 1 次编造；1 = ≤1/5 或多次编造

### 2.2 长文摘要质量

- **任务**："用 300 字输出这份报告的结构化摘要，覆盖核心结论和关键数据"
- **观察点**：核心章节覆盖度、关键数据是否忠实原文、有无无中生有
- **锚点**：5 = 覆盖全且数据准确；3 = 覆盖主要章节但丢关键数据；1 = 遗漏大半或数据错误

### 2.3 上限与稳定性

- **任务**：记录各产品官方标称的上下文/文件大小上限；实测上传材料 C 是否顺利，若有更大文档可加测
- **观察点**：标称 vs 实际；超限时的行为是明确提示还是静默截断（静默截断扣分）
- **锚点**：5 = 上限高且超限提示明确；3 = 上限一般、行为可预期；1 = 静默截断或频繁失败

## 三、Agent 自动任务完成度（3 项）

> 说明：DeepSeek 官方应用无 Agent 插件生态，按实际表现打分即可——"能力缺失"本身就是评测结论，不做豁免。

### 3.1 复合任务拆解

- **任务**："这是我的简历（材料 A）和目标 JD（材料 B）：①分析匹配度 ②列出我的差距 ③给出一周准备计划"
- **观察点**：三个子任务是否都完成？是否有结构化的分步执行？
- **锚点**：5 = 三项齐全且逻辑连贯；3 = 完成 2 项或混在一起；1 = 只答了一件事

### 3.2 工具调用与信息时效

- **任务**："查一下【JD 对应公司】最近三个月的产品动态，总结对我面试的启示"
- **观察点**：是否调用联网搜索？信息是否有时效性（2026 年内）？是否给出来源？
- **锚点**：5 = 联网、信息新、有来源；3 = 联网但信息旧或无来源；1 = 不联网硬编

### 3.3 端到端交付质量

- **任务**：沿用 3.1 的输出，评"能不能直接拿来用"
- **观察点**：一周计划是否具体到天、可执行？匹配度分析是否引用了 JD 原文关键词？
- **锚点**：5 = 直接可用无需加工；3 = 框架对但需大量自己填充；1 = 正确的废话

## 四、垂直场景适配性（求职场景，3 项）

> 本维度同时是自研产品的对照实验：跑完四个产品后，把同样任务在自己的简历优化助手上跑一遍作为第五列参照。

### 4.1 简历优化专业度

- **任务**："我目标岗位是 AI 产品实习生（附材料 B），帮我优化这段经历（附材料 A）"
- **观察点**：是否用 STAR 结构？是否给出量化建议？是否解释每处修改的理由？
- **锚点**：5 = STAR + 量化 + 逐条理由；3 = 改得更通顺但无方法论；1 = 仅润色辞藻

### 4.2 JD 关键词匹配意识

- **任务**：沿用 4.1 输出分析
- **观察点**：优化结果是否主动融入 JD 中的关键词？是否指出经历与 JD 的能力缺口？
- **锚点**：5 = 关键词自然融入且指出缺口；3 = 少量关键词、不提缺口；1 = 与 JD 无关

### 4.3 输出泛化程度（反向验证）

- **任务**：同一段材料 A，分别配材料 B（AI 产品）和材料 D（后端开发）各优化一次
- **观察点**：两次输出差异有多大？差异小 = 模板化输出，不管什么岗位都给同一套话术
- **锚点**：5 = 两版侧重点明显不同、贴合各自岗位；3 = 部分调整；1 = 几乎一样（泛化实锤）
- **意义**：此项直接验证"通用大模型在垂直求职场景输出泛化"的核心结论
