# Coze Agent 设计方案：「AI 求职策略顾问」

> **搭建平台**：[coze.cn](https://www.coze.cn)（字节跳动扣子，免费版）
> **定位**：JD 解析 → 匹配度分析 → 面试准备方案的完整链路 Agent
> **与 Streamlit 简历优化器的关系**：互补。Streamlit 做简历文本优化，Coze Agent 做求职策略咨询

---

## 一、为什么搭这个 Agent

当前 AI 产品实习生 JD 中，Agent/工作流编排经验的提及率已达 38%，是 AI PM 与传统 PM 岗位的关键区分点。这个 Agent 直接证明了你能：

1. **在 Coze 平台编排多节点工作流**（非简单 LLM 调用）
2. **设计条件分支 + 数据库 + 插件 + LLM 的复合链路**
3. **从产品视角设计 Agent 的人设、知识库、交互流程**

面试官在 Coze 画布上能看到你的工作流设计——这比简历上写「熟悉 Agent 编排」可信得多。

---

## 二、产品定位

| 维度 | 说明 |
|------|------|
| **一句话定位** | 帮求职者从 JD 解析到面试准备一条龙的 AI 策略顾问 |
| **核心功能** | JD 深度解析 → 简历匹配度分析 → 个性化面试准备方案 |
| **目标用户** | 应届生 / 实习生求职者（可扩展到全人群） |
| **差异化** | 不是简单的「粘贴 JD → 出结果」，而是有数据库记忆、条件分支、多步骤推理的工作流 |

## 三、技术架构

### 模式选择：单 Agent + 工作流（免费版可用）

多 Agent 模式需要 Coze 专业版。采用免费版可落地方案：**一个 Bot + 一个 Workflow**。

### 工作流节点设计（7 个节点）

```
┌──────────┐    ┌──────────────┐    ┌──────────────┐
│  Start   │───▶│ Fetch JD     │───▶│ Parse JD     │
│ 接收输入  │    │ Web Reader   │    │ LLM 结构化    │
└──────────┘    │ Plugin 抓页面 │    │ 提取 JSON    │
                └──────────────┘    └──────┬───────┘
                                           │
                              ┌────────────▼────────────┐
                              │  Check Profile          │
                              │  Condition 分支          │
                              │  数据库中有存档简历？     │
                              └──────┬────────┬─────────┘
                                     │YES     │NO
                           ┌─────────▼──┐  ┌──▼───────────┐
                           │ Load Profile│  │ Ask for Info │
                           │ Database    │  │ LLM 询问关键 │
                           │ 读取存档    │  │ 经历          │
                           └──────┬──────┘  └──┬───────────┘
                                  │            │
                                  └─────┬──────┘
                                        │
                              ┌─────────▼──────────┐
                              │ Gap Analysis       │
                              │ LLM 匹配度分析      │
                              │ 优势区 / 短板区     │
                              └────────┬───────────┘
                                       │
                              ┌────────▼───────────┐
                              │ Prep Plan           │
                              │ LLM 面试准备方案     │
                              │ 5题+3故事+策略建议   │
                              └────────┬───────────┘
                                       │
                              ┌────────▼───────────┐
                              │ End                 │
                              │ 结构化报告输出       │
                              └─────────────────────┘
```

### 节点详情

| 序号 | 节点名 | 类型 | 输入 | 输出 | 关键配置 |
|------|--------|------|------|------|----------|
| 1 | Start | Start | `jd_input`: string (URL 或文本) | → 传给下一节点 | — |
| 2 | Fetch JD | Plugin: Web Reader | jd_input | 网页正文 or 原文本 | 仅当 jd_input 是 URL 时生效 |
| 3 | Parse JD | LLM | 网页正文/原文本 | JSON: `{company, role, must_have[], nice_to_have[], responsibilities[], keywords[], signals[]}` | 使用结构化输出 |
| 4 | Check Profile | Condition | — | YES / NO 分支 | 判断数据库是否有用户简历 |
| 5a | Load Profile | Database | user_id | `{skills[], experience[], education, target}` | 新建数据表 `user_profiles` |
| 5b | Ask for Info | LLM | 用户输入 | 临时构建 profile | 询问：技能、项目经验、教育背景 |
| 6 | Gap Analysis | LLM | JD_req + user_profile | JSON: `{strengths[], weaknesses[], match_score, priority[]}` | 核心推理节点 |
| 7 | Prep Plan | LLM | gap_result | Markdown 报告：面试题 + 故事建议 + 策略 | 最终输出 |
| 8 | End | End | 报告 | 输出到聊天 | — |

### 快捷模式：「简历诊断」

单独一个意图分支（通过 Bot 人设 Prompt 判断）：
- 用户直接粘贴简历文本 → Agent 用 STAR 法则打分
- 输出：3 个优点 + 3 个改进点 + 1 个最优先修改建议
- 这个模式轻量、无需 JD，面试官可以随手试用

## 四、Bot 人设 Prompt

```
你是「小策」，一位 AI 求职策略顾问。你擅长：
1. 深度解析 JD，提取隐性要求和公司文化信号
2. 对比 JD 与求职者背景，精准定位匹配度和短板
3. 生成个性化的面试准备方案

你的交互风格：
- 专业但不冰冷，像一位有经验的学长/学姐
- 给出的建议具体、可执行，不说"好好准备"这类废话
- 如果信息不足，主动追问，但不连续问超过 2 个问题

你可以处理两种请求：
A. 用户发送 JD 链接或粘贴 JD 文本 → 调用 JD 解析工作流
B. 用户粘贴简历文本 → 直接用 STAR 法则诊断，给出 3 优点 + 3 改进点
```

## 五、知识库内容

| 分类 | 具体内容 | 来源 |
|------|----------|------|
| **简历写作** | STAR 法则、量化方法、动词库、行业规范 | 复用 Streamlit 项目的示例知识库 |
| **AI PM 面试题库** | 30+ 题，分产品 sense / 技术 / 行为 / case 四类 | 结合你的竞品分析经验自编 |
| **公司面试风格** | 字节（重数据+逻辑）、腾讯（重产品感）、创业公司（重落地）等 | 网上搜集 + 内推消息整理 |

## 六、数据库设计

在 Coze 数据库节点创建表 `user_profiles`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | 自动编号 | 主键 |
| `name` | 文本 | 用户名称 |
| `skills` | 文本（逗号分隔） | 技能标签 |
| `experience_summary` | 长文本 | 核心项目经历摘要 |
| `education` | 文本 | 学校 + 专业 |
| `target_role` | 文本 | 目标岗位 |
| `target_city` | 文本 | 目标城市 |
| `resume_full` | 长文本 | 完整简历文本 |

## 七、搭建步骤（Copilot，在 Coze 网页端操作）

### Step 1：注册 & 创建 Bot

1. 浏览器打开 [coze.cn](https://www.coze.cn)，用手机号注册
2. 点击「创建 Bot」→ 填写：
   - 名称：`AI求职策略顾问`
   - 描述：`帮你解析 JD、评估匹配度、生成面试准备方案`
   - 图标：自选
3. 在人设页面粘贴上面的人设 Prompt

### Step 2：搭建工作流

1. 进入 Bot 编辑页 → 点击「工作流」→「创建工作流」
2. 按三中节点表逐个添加节点
3. 关键配置：
   - **Web Reader 插件**：在插件市场搜索「Web Reader」或「链接读取」
   - **条件分支**：设置判断变量 → 引用数据库查询结果
   - **LLM 节点**：每个 LLM 节点单独写 Prompt，设置 JSON 输出格式

### Step 3：上传知识库

1. 在 Bot 编辑页 →「知识库」→「创建知识库」
2. 上传准备好的文档（面试题、写作指南等）
3. 在 Bot 设置中关联知识库

### Step 4：配置数据库

1. 在 Bot 编辑页 →「数据库」→「创建数据表」
2. 按照六中的 schema 建表

### Step 5：发布

1. 点击右上角「发布」
2. 选择「H5 网页」作为发布渠道
3. 获取链接 + 二维码

### Step 6：截图 + 记录

1. 截图工作流画布（完整，显示所有节点连线）
2. 截图 Bot 对话效果（用真实 JD 测试）
3. 保存到作品集文件夹

## 八、给面试官的演示脚本

> 整个演示控制在 3 分钟内

**30 秒 | 我为什么做这个**
"我的 Streamlit 项目解决了简历文本优化问题，但求职不只是改简历——从看到 JD 到面试准备之间还有大量工作。这个 Coze Agent 补齐了这条链路。"

**90 秒 | 工作流走查**
打开 Coze 工作流画布，从 Start 节点开始走到 End：
"这里是 7 个节点的流水线——网页抓取插件处理 JD 链接，LLM 做结构化提取，条件分支判断用户有没有存简历，如果有就从数据库读，如果没有就现场问，然后做匹配度分析和面试准备方案生成。"

**60 秒 | 现场演示**
粘贴一个真实 JD（或链接），让 Agent 跑一遍。展示输出的结构化报告。

**30 秒 | 能力总结**
"这个 Agent 展示了我在 Coze 平台上编排多节点工作流、配置知识库和数据库、设计条件分支的能力——这些都是 AI PM 日常工作中 Agent 产品设计的基本功。"
