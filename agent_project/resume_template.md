**产品定位**：面向应届生的 AI 简历优化工具，集成 RAG 知识增强 + 多模型调度 + 自动化效果评估，支持 Markdown / DOCX 一键导出。

在线 Demo：https://resume-optimizer-fk6i2k98yaata3wkh6owab.streamlit.app/

- **需求分析与产品定义**：通过用户访谈与社区发帖收集应届生简历样本，提炼「缺乏量化表述」「STAR 法则缺失」「JD 关键词匹配度低」三项高频痛点，据此圈定产品核心功能边界并撰写需求文档
- **产品方案与 Prompt 体系设计**：设计「HR 诊断式」对话交互模式，落地「问题诊断→优化建议→修改理由→效果评分」四段式标准化输出框架；通过角色设定、输出格式、评估维度等变量持续迭代 Prompt，沉淀可复用的 Prompt 设计方法论
- **RAG 知识增强设计**：针对通用大模型在求职场景输出泛化、专业度不足的问题，设计 RAG 知识增强方案——基于 Chroma 搭建向量知识库，以 TF-IDF / BGE 双 Embedding 与多路召回（向量语义 + 关键词 + 重排序）保证检索覆盖率，内置简历写作指南，支持用户上传 HR 规范 / JD 模板扩展知识源
- **自动化评估体系**：为降低产品迭代验证成本，设计三维 LLM 自动打分体系（完整性 / 岗位匹配度 / 格式规范度）替代人工逐条评审，输出优化趋势折线图与 CSV 数据报告，支撑版本间效果对比
- **商业化与多用户设计**：面向公开部署设计免费增值（Freemium）用量策略——每用户每功能 3 次免费额度，超出后引导 BYOK（用户自带 API Key）解锁不限量、本地模型豁免；无登录体系下以 IP 哈希 + 服务端持久化实现用户级限流，用户密钥仅存会话内存、明文 IP 不落盘，并修复多会话共享进程下用户密钥跨会话泄漏风险，兼顾 API 成本防护与隐私安全
- **开发部署与迭代规划**：基于 Streamlit 完成前端搭建与 Streamlit Cloud 云端部署，上线公网 Demo 可直接体验；集成 PRD 文档自动生成、NPS 用户调研、数据看板等辅助模块；基于内测反馈整理功能优先级 Backlog，规划 V2.0 增加 JD 匹配度分析与 PDF 简历自动解析

### AI 产品横向测评研究 ｜ 独立研究 ｜ 2026.03 – 至今

**研究目的**：为明确自研简历工具的产品定位，对主流 AI 产品进行聚焦求职场景的系统化横向评测，结论直接驱动产品设计决策。

评测方案与全量证据（公开可查）：https://github.com/addws1/resume-optimizer/tree/main/docs

- **评测框架设计**：自建四维评测框架（对话交互体验 / 长文档处理能力 / Agent 任务完成度 / 垂直场景适配性），拆分为 12 项细分指标，每项配统一测试任务与 1–5 分锚点评分标准，确保评测可复现、可对比
- **全量执行**：完成四维 12 项指标全量实测（豆包 / Kimi / DeepSeek 全量，Coze 因服务限流部分完成并如实记录）——统一简历样本 + 双岗位 JD 对照 + 统一长文档问答 + 带真值核查的检索任务，留存 40+ 组全文对话证据与逐项打分依据
- **核心发现**：①交互层共性缺陷——4/4 产品不追问目标岗位即直接输出优化；②编造行为呈场景依赖规律——文档问答任务全员零编造，"补充量化表述"指令诱导 3/3 产品虚构数据，检索任务出现"真实热点嫁接假新闻"的失效模式；③预设的"跨岗位输出模板化"假设被实测数据推翻，依据数据修正结论
- **产品决策驱动**：实测发现逐一转化为自研产品设计决策——表单强制输入目标岗位（对应缺陷①）、输出内置修改理由与基于原文不虚构成果（对应缺陷②），并据此确立"可解释、不编造"的垂直场景差异化定位
