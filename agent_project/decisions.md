## 决策记录

| # | 日期 | 决策 | 理由 | 备选方案 |
|---|------|------|------|---------|
| 1 | 2026-07-25 | 项目方向：**简历优化 Agent**（方向1） | 现有简历优化器的升级，有积累不重来；Agent 多轮自审+文件上传+DOCX 输出，展示产品迭代思维 | 方向2（AI产品评测Agent）偏通用不够聚焦；方向3（招聘筛选Agent）贴合TTC但用户当前更想深耕已有方向 |
| 2 | 2026-07-25 | Agent 行为模式：**一键到底**（模式A） | MVP 阶段先跑通核心链路，减少用户操作步骤；后续迭代再加逐步确认模式 | 模式B（逐步确认）控制感强但点击多；模式C（混合）开发量大，0→1阶段不划算 |
| 3 | 2026-07-25 | 输入方式：**文本粘贴 + 文件上传两者都支持**（方案C） | 粘贴保留给快速使用的老用户；文件上传是本次核心升级——"能上传简历的App"比"贴文本的网页"更像产品 | 方案A（仅粘贴）太保守；方案B（仅上传）丢了快速使用场景 |
| 4 | 2026-07-25 | 输出格式：**屏幕展示 + DOCX 下载**（方案C） | 屏幕展示给即时反馈，DOCX 用于保存/投递——优化完就是要拿去用的 | 方案A（仅展示）用户拿不走；方案B（仅DOCX）等待过程焦虑 |
| 5 | 2026-07-25 | 内容结构：**四栏 + Agent 自审痕迹**（方案C） | 四栏已验证有效，保留；自审痕迹是"Agent vs 普通LLM"的核心差异化——面试演示时能展示Agent的思考迭代过程 | 方案A（保持四栏）没有体现Agent升级；方案B（精简版）丢了对比价值 |
| 6 | 2026-07-25 | Agent 自审轮数：**固定 2 轮**（方案A） | MVP 阶段 2 轮足够展示自审改进价值；3 轮边际收益递减；动态轮数有死循环风险且用户无法预期等待时间 | 方案B（3轮）多一次调用但收益不明显；方案C（Agent自判）不确定性强，成本不可控 |
| 7 | 2026-07-25 | 等待体验：**分步状态更新**（方案B） | 30秒+等待需要告知进度，降低焦虑；现有 st.status 组件即可实现，开发成本低 | 方案A（静态提示）用户不知道还要等多久；方案C（流式展示中间结果）MVP过度设计，中间结果可能误导用户 |
| 8 | 2026-07-25 | 错误处理：**分步兜底**（方案B） | 多步骤流程每步都可能挂，需告知用户"哪一步出错 + 怎么解决"；A类错误给修复指引，B类错误给降级提示 | 方案A（单catch-all）用户只能看到技术错误信息无法自救；方案C（优雅降级）MVP过度设计 |
| 9 | 2026-07-25 | 目标岗位/公司输入：**放到主页面**（方案B） | 侧边栏发现性太差，很多用户不知道能填；主页面可选填，不填也能优化 | 方案A（保持侧边栏）发现性低；方案C（Agent主动问）与"一键到底"冲突，体验割裂 |
| 10 | 2026-07-25 | RAG 知识库：**MVP 先砍掉**（方案B） | Agent 自身能力+自审已构成核心价值；同时做 Agent loop + RAG 工具调用复杂度翻倍，先验证 Agent 自审价值 | 方案A（保持注入）没有 Agent 感；方案C（RAG变工具）方向对但 MVP 两个新东西一起上风险高 |
| 11 | 2026-07-25 | 结果后交互：**支持一轮追问**（方案B） | 用户看到结果后能提一次修改意见→Agent 针对性改版；覆盖"再改改"80%场景，开发量可控 | 方案A（不能追问）不满意只能重来；方案C（多轮对话）上下文膨胀风险+开发量大，MVP后迭代 |
| 12 | 2026-07-25 | 文件上传：**PDF + DOCX，10MB，拖拽上传** | PDF+DOCX 覆盖~95%简历场景；10MB 足够大不限正常使用；Streamlit 原生支持拖拽 | 仅PDF（覆盖60%太低）；加图片OCR（另一个问题领域，MVP不做） |
| 13 | 2026-07-25 | 评分系统：**砍掉定量打分，换成 Agent 自评总结**（方案C） | LLM 自评分数无 Ground Truth，本质不可靠；Agent 定性解释"改了什么、为什么"更诚实、更有可解释性 | 方案A（保留打分）有回声室问题且无Agent感；方案B（全砍）丢了质量反馈 |
| 14 | 2026-07-25 | 项目范围：**全新独立项目**（方案B） | 老项目是 PM 学习路线见证，保留；Agent 项目独立展示"单次调用→Agent自审"进化，叙事更清晰 | 方案A（全保留+Agent）定位模糊；方案C（精简合并）两头不讨好 |
